# 发布更新

当用户要求“发布更新”、“部署更新”、“上线最新代码”或类似表达时，使用本 skill 执行 clothes-design 项目的远程发布流程。

## 目标

通过 SSH 连接服务器 `user@74.48.78.127`，进入项目目录 `Code/clothes-design/`，拉取最新代码，然后重新构建并后台启动 Docker Compose 服务。

## 固定发布命令

优先执行以下远程命令，不要改动服务器地址、用户名或项目目录，除非用户明确要求：

```bash
ssh user@74.48.78.127 'cd Code/clothes-design/ && git pull && docker compose build && docker compose up -d'
```

## 执行要求

1. 直接运行发布命令，不要先询问是否继续。
2. 完整保留命令输出，用于判断发布是否成功。
3. 如果命令成功，简洁说明发布完成，并总结关键输出，例如代码是否更新、镜像是否构建、容器是否启动。
4. 如果命令失败，必须返回易读错误，包含：
   - **失败步骤**：SSH 连接、进入目录、`git pull`、`docker compose build` 或 `docker compose up -d`。
   - **错误摘要**：用 1-2 句话解释发生了什么。
   - **可能原因**：例如 SSH 不通、权限不足、目录不存在、Git 冲突、Dockerfile 构建失败、镜像拉取失败、端口占用或 Compose 配置错误。
   - **原始关键信息**：摘录最相关的错误输出，不要整段堆砌噪音。
5. 如果失败输出不足以判断具体步骤，可以根据命令输出推断最可能的失败点，并明确说明“根据输出推断”。

## 输出格式

成功时：

```text
发布完成。
- 代码：...
- 构建：...
- 服务：...
```

失败时：

```text
发布失败：<失败步骤>

发生了什么：<易读说明>
可能原因：<解释>
关键错误：<摘录>
```

## 注意事项

- 不要在本地执行 `git pull` 或 `docker compose` 来代替远程发布。
- 不要吞掉错误输出；发布失败时，错误信息比“失败了”本身更重要。
- 不要提交代码，除非用户明确要求。
